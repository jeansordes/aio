# Run Foreground Goal Session

- In a terminal, bare `aio` offers to resume an unfinished session or start a
  new goal. A new goal requires an objective and at least one success criterion.
  A completed session remains on disk until replaced by a new goal.
- Cursor Agent and Codex are available when installed. Additional headless
  harnesses can be configured in `.aio/providers.yaml` with prompt input via an
  argument containing `{{prompt}}` or via `promptInput: stdin`.
- Each turn starts a fresh harness process with the objective, criteria,
  last completed checkpoint and operator guidance. Output is visible in the
  terminal. A successful harness exit and a valid report for that turn are
  required to update the checkpoint. Completion requires one reported piece
  of evidence per criterion, displayed with the criterion it supports.
- A request for operator input, a failed turn, ten completed turns since start
  or resume, or an operator pause stops new turns. `p` then Enter waits for the
  current turn to finish. At a pause, the user can give guidance before resuming.
- `q` then Enter, Ctrl+C and terminal closure stop the harness. aio retains the
  last completed checkpoint and warns on interruption that project files may
  already contain changes. A turn interrupted before it completes does not
  count, even if it already wrote a report.
- Keep one active session per project, with atomic checkpoints and an exclusive
  lock under `.aio/sessions/goal/`. Session artifacts are ignored by Git. aio
  releases the lock on normal shutdown; after a forced kill, a stale lock may
  be removed once the previous aio and harness processes have stopped.
