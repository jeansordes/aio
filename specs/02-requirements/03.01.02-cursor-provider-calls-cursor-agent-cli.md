# Provider Config Calls Cursor Agent CLI

The generated `.aio/providers.yaml` must configure the [Cursor Agent CLI](https://cursor.com/docs/cli) (`cursor-agent` on `PATH`).

- Build a text prompt from role instructions, context file paths, and `projectKnowledge` including `trackingFile`. Roles may include `run_dir` in `prompt.include` to pass the active `runId` and `runDir`.
- Run `cursor-agent` in non-interactive print mode, for example: `-p`, `--force`, `--trust`, `--output-format stream-json`, `--stream-partial-output`, `{{isolation_args}}` (workspace + sandbox when isolation is enabled), and `{{prompt}}`. Support optional `--model` when the role’s model is not `default`.
- Require `CURSOR_API_KEY` (or the CLI’s normal auth) in the user environment.

`aio init` uses a successful `cursor-agent` version probe (see `03.01.03`) to
treat the Cursor provider as available before creating `.aio/`.

The runner captures the agent’s stdout and stderr as logs. Workflow state comes
from the process exit status and working tree changes, not from parsed AI output.
Other generated providers may remain not-configured entries.
