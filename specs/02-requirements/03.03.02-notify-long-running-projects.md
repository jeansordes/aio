# Notify Long Running Projects

Long-running workflows can notify the user from unattended environments such as
a VPS.

Notifications should cover:
- workflow started
- workflow completed
- workflow failed
- usage threshold reached
- user attention required

Initial delivery can use webhooks.
Discord is a preferred first target because it supports project channels,
mentions, and simple operational alerts.

Implemented subset: `aio run` posts to a Discord incoming webhook when
`DISCORD_WEBHOOK_URL` is set in `.aio/.env` (optional `DISCORD_MENTION_USER_ID`).
Messages are queued to reduce rate-limit risk. Step posts include status, timing,
changed files when present, and optional per-step AI summary (`03.03.05`).
Threshold-based and attention-specific notifications remain future work.
