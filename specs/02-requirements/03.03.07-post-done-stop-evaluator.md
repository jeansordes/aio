# Post-Done Stop Evaluator

**Status:** not implemented (roadmap `03.03.07`, `todo`).

Some operators want a single `aio run` to continue or terminate based on
**aggregate** criteria evaluated after the workflow reaches a final state, for
example:

- all tasks in a list are complete
- a quality score meets a target
- cost or token spend exceeds a budget
- several iterations show no improvement

Future work: a workflow-level `stop` (or equivalent) block parsed by the
runtime, evaluated after the `done` node, deciding whether to re-enter the graph
or exit the process. Until then, looping is expressed only inside one workflow
invocation using `next:` transitions (and limited by `workflow.maxSteps`).

See also [`03.03.01`](03.03.01-limit-workflow-loops.md) (superseded CLI loop counts).
