# Global Notification Webhooks

Optional notifications in the global aio config apply to all projects on this
user account/machine. Support generic JSON webhooks, ntfy text publication,
Discord incoming webhooks and Pushover form submission. Targets have unique
names, type, URL, optional headers, and Pushover token/user fields. URL, header
values and credentials support ${ENV_VAR}; secrets are never copied to sessions.

Default events are paused and completed; started and resumed are opt-in.
Pauses include user requests, limits, failures and interruption. Payloads identify
the machine, project, workflow and node, with a bounded reason/result message;
never send whole transcripts or prompts. Discord disables automatic mentions.
HTTP acceptance is recorded as accepted, not proof of device receipt. Pushover
also requires status=1. Do not follow redirects.

Send asynchronously in event order, in parallel across up to ten destinations.
Bound the queue to sixteen events and each request to three seconds by default
(configurable 100–10000 ms). No automatic retries. Flush pending sends at pause
or completion before prompting. Each flush gives pending sends one timeout window
before cancelling requests and dropping queued events with a warning. Errors produce sanitized warnings and delivery metadata,
never response bodies, request credentials or URLs; they do not change workflow
results. Invalid config is reported at load; an unresolved destination is skipped
with a warning while other destinations remain usable.
