# Stream Runtime Logs

Workflow runs expose a real-time feed of actions and messages.

The feed lets the user inspect what agents are doing while a project runs.
It should include state transitions, provider calls, notable messages, warnings,
errors, and attention requests.

Implemented:
- `.aio/runs/<id>/events.jsonl` — structured events (chunks summarized for stdout/stderr)
- `.aio/runs/<id>/conversation.log` — append-only transcript of provider output (verbatim provider stream, including NDJSON when that is the provider format)
- `.aio/runs/latest` — id of the most recent run
- Terminal live view during `aio run` (streamed provider stdout/stderr; `--quiet` for milestones only; on a TTY, idle heartbeat with exponential backoff and elapsed seconds when the provider is quiet; default Cursor template uses `stream-json` plus `--stream-partial-output`, and the terminal sink renders assistant deltas and tool-call lines instead of raw NDJSON unless `--verbose`, which copies NDJSON lines to stderr)
- `aio observe` — follow `conversation.log` or `events.jsonl` (`--events`) for a run (`--run <id>` or latest)

Still open:
- generic webhook event stream beyond Discord
- redaction rules for secrets and sensitive project content
