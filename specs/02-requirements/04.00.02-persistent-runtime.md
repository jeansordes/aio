# Persistent Runtime

One runtime executes a Goal/end graph or a multi-node workflow. Every invocation
starts a fresh harness with the current node, guidance, current checkpoint and
summaries of prior node results; complete results remain in session.json.
Goal reports are continue, done (evidence for every criterion), or blocked
(summary plus user request). Route reports select a listed destination and give
a summary/justification, or request user input. Routes may inspect files; prompts
prohibit project modifications, without claiming universal sandbox enforcement.
An exit code alone never establishes node completion.

Atomically save the accepted report and destination together. Revisited nodes get
a new visit and fresh turn count while retaining historical results. Snapshot the
workflow and chosen defaults on start; resume uses the snapshot. Invalid reports,
unavailable harnesses and nonzero exits pause with an explanation.
Pause after maxTurns (10) on a Goal or maxInvocations (100) across the graph.
Resuming explicitly resets these execution-window limits. Errors and interruptions
never commit the in-flight report. Quitting stops the process group including
tools; signal escalation prevents a nonresponsive harness from hanging shutdown.

Use one locked .aio/sessions/current session with atomic checkpoints, persistent
events and output logs ignored by Git. Mark interrupted checkpoints on recovery.
A stale lock after forced termination requires checking the old processes have
stopped before removing it.
