# Persistent Runtime

One version 2 runtime executes action, route, script and end nodes. Every agent
invocation is fresh, with project state, guidance and prior results. Action reports
are done with summary or blocked with summary/request. Routes select an authorized
destination with justification, or block. Criterion routes supply exactly one
satisfied/not_satisfied/indeterminate status and evidence per criterion. End routes
require all satisfied; indeterminate needs a blocked report and user request.
Routing prompts prohibit modifying project work; this is not a universal OS sandbox.

Scripts execute command/args in the project with no implicit shell. Fixed scripts
advance on exit 0; routing scripts emit a single JSON {to, summary} on stdout,
with diagnostics on stderr. Nonzero exit, malformed/oversized routing output and
timeout (default ten minutes) pause without model fallback. Stop the process group
on timeout, interruption or leader exit, including descendants holding pipes open.

Resolve profiles from the session snapshot, in list order. Skip absent executables.
Only recognized model-unavailable/quota/rate-limit failures on unsuccessful exits
or explicit structured stream error records trigger fallback, even if the CLI
exits zero. Diagnostics come from stderr or structured stdout error records.
Unknown errors and invalid reports pause. Stop the prior process group before any
fallback. Keep partial edits and tell the next agent to inspect actual project state.
Record selected profile, entry index, harness, requested model and fallback reason.
Suppress unavailable pairs for the current execution window, reset on explicit resume.
Count every launched process toward maxInvocations (default 100); explicit resume
resets the window. Exhaustion pauses. User pause is honored between invocations.

Atomically save accepted results and destinations. Preserve visits, output and
events in one locked current session. Recovery marks interrupted invocations.
Snapshot workflow, referenced profiles and concrete harness definitions. Old session
versions are incompatible; starting a new session archives the prior directory with
no automatic migration or deletion. Restore the archive if new-session creation fails.
Notification delivery remains bounded and errors never invalidate agent work.
