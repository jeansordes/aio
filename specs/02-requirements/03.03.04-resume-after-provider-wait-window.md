# Resume After Provider Wait Window

Workflows can pause when a provider reaches a time or credit window.

Provider wrappers for tools such as Codex and Claude should detect structured
or known textual signals that the current session must wait before more work can
continue. When this happens, the runner records the workflow state, schedules a
resume time when it can infer one, and stops active provider calls.

The user is notified when:
- the workflow pauses because a provider limit was reached
- the runner is waiting for a known or estimated resume time
- the workflow resumes
- the workflow cannot infer a safe resume time and needs attention

After the wait window expires, the runner relaunches the plan from the saved
state and continues until completion or until another configured guardrail is
reached.

Open design:
- provider-specific limit parsers
- explicit resume timestamps versus conservative backoff
- persistence format for resumable workflow state
- interaction with token budgets, loop caps, and notification channels
