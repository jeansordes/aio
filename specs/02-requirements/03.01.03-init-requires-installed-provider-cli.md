# Init Requires Installed Provider CLI

`aio init` and `aio setup` must not scaffold `.aio/` until the machine has at
least one runnable provider CLI that aio can wire up without hand-editing
`.aio/providers.yaml` first.

For the current template, that means `cursor-agent` is on `PATH` and responds
to a version probe (for example `cursor-agent --version` with exit code `0`).

If no such provider is found, the command fails with a clear error. The message
explains that aio needs a local LLM provider CLI, points to installing the
Cursor Agent CLI when applicable, and mentions configuring the `custom` entry
(or another provider block) in `.aio/providers.yaml` after the user can invoke
a CLI on their system.

If a provider is found, new role files bind to that provider so the default
workflow can execute against the configured command instead of defaulting to an
unconfigured `custom` role.

Tests may inject a probe so automated runs do not depend on a real CLI install.
