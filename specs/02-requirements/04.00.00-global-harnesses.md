# Global Harnesses And Model Profiles

Harness definitions live in XDG_CONFIG_HOME/aio/config.yaml or ~/.config/aio/config.yaml.
Cursor and Codex are built in; custom CLI commands accept a prompt argument or stdin.
Relative executable paths resolve from the global configuration directory.
Authentication belongs to each CLI. ACPX and model-based fallback selection are out of scope.

model-profiles.yaml in the same directory contains profiles mapping user-defined
names directly to nonempty ordered lists of {harness, model}. Entries use explicit
CLI model identifiers; no invented identifiers or silent model substitution.
Offer low, mid and high during setup; actions default to mid and routes to low.
Agent nodes reference modelProfile only. Snapshot referenced profiles and concrete
harness definitions on session creation. Missing profiles or unsupported model
argument configurations prevent launch. Unavailable executables are handled by
runtime fallback. Profile persistence is atomic and global, independent of projects.
Only recognized model-unavailable, quota and rate-limit failures qualify for repli.
