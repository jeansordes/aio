# Limit Workflow Loops (superseded)

**Superseded as of 0.12.0:** `aio run` no longer accepts a loop count on the CLI.
Each invocation runs the workflow **once** (one `runId`, one `.aio/runs/<id>/`
directory). To repeat work or cycle through states, encode **transitions** in
the workflow YAML (`next:` branching back to earlier states). The safety cap on
how many states execute in one invocation remains **`workflow.maxSteps`** in
`.aio/config.yaml` (see the engine loop in `runWorkflow`).

**SIGINT:** first interrupt finishes the current run after the workflow returns;
second interrupt aborts the in-flight provider (SIGTERM, then SIGKILL after a
short grace).
