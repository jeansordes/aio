# Limit Workflow Loops

Operators control how many times `aio run` executes the same workflow in a row.

Implemented in the CLI:

- `aio run` — one loop (default).
- `aio run <n>` — when `<n>` is a non-negative integer and no workflow name is
  given, run the default workflow `<n>` times (use `0` for infinite loops until
  SIGINT).
- `aio run <workflow> <n>` — run the named workflow `<n>` times (`0` = infinite).
- `--loops N` / `-n N` — same as the numeric second positional argument; do not
  combine with a second positional loop count.

Each loop is independent: a new event bus, new `runId`, and new `.aio/runs/<id>/`
directory. Memory between loops is project files only.

**SIGINT:** first interrupt finishes the current loop after the workflow returns;
second interrupt aborts the in-flight provider (SIGTERM, then SIGKILL after a
short grace).
